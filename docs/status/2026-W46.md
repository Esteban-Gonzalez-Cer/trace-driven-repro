## Blockers and risks

- **Screening yield is low, as the spec warned:** 25 candidates screened, 5 validated. Most
  "fix" PRs are not crashes: their regression tests fail with an `AssertionError` in the test
  (wrong output), not an exception from library code.
- **Test runners that swallow crashes:** click's `CliRunner` catches exceptions, so a click crash
  shows up as a failed output check (click-3582 excluded). Expect the same for typer.
- **Dev-set diversity:** 3 of 5 dev bugs are from marshmallow. Fine for iterating on the harness
  (the dev set's only purpose), but the test set should spread across libraries.
- **"Crash" includes library exceptions on valid input:** marshmallow-3016 and -3082 raise
  `ValidationError` for valid data. That meets criterion 1 as written (an uncaught exception
  with a stack trace), but it is a softer kind of crash than an `int()` failure. Worth a
  conscious decision before test-set screening.
